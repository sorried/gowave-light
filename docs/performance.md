# проверка ресурсов и изменений

замеры выполнены 2 ноября 2026 года. исходный код: `7c7e866`, оптимизации: `385c01c`. тесты добавлены отдельными коммитами перед изменениями кода. новые зависимости не добавлялись.

## что изменилось

- копирование метрик узла выполняется напрямую, включая вложенные указатели и срезы. JSON больше не создаётся под блокировкой кеша.
- при повторной синхронизации узла читаются только `id` и `vless_uuid`, порциями по 500 пользователей. постановка заданий и повтор ранее неудачных заданий остаются в одной транзакции.
- удалены повторные вызовы синхронизации после фиксации пользователя. задания уже сохраняются внутри транзакции. также удалены неиспользуемые поля, интерфейсы и методы настройки этих вызовов.
- генерация идентификаторов и паролей читает случайные байты пачками. используется `crypto/rand`, прежний алфавит и отбрасывание значений вне кратного алфавиту диапазона, чтобы сохранить равные вероятности символов.
- удалён закомментированный код запуска frontend. браузерные тесты завершаются при отсутствии Chrome и повторяют проверку, если начальная навигация уничтожила контекст страницы.

## отдельные операции

Linux amd64, Intel Core i7-11700F, Go `1.27.2-X:nodwarf5`. тестовые бинарники запускались последовательно с `GOMAXPROCS=1` и привязкой к CPU 14. для метрик и синхронизации выполнено пять повторов, для идентификаторов три. ниже медианы. другие приложения на компьютере продолжали работать.

| операция | время до → после | байт на операцию до → после | выделений до → после |
| --- | --- | --- | --- |
| копирование метрик | 7,668 → 0,367 мкс | 1224 → 536 | 16 → 12 |
| синхронизация 1000 пользователей | 39,052 → 29,579 мс | 20 700 064 → 10 164 169 | 169 030 → 99 092 |
| идентификатор, 16 символов | 1,644 → 0,161 мкс | 784 → 16 | 49 → 1 |
| пароль, 32 символа | 3,220 → 0,192 мкс | 1568 → 32 | 97 → 1 |
| идентификатор, 64 символа | 6,431 → 0,404 мкс | 3200 → 128 | 194 → 2 |

для синхронизации использована SQLite в памяти. у каждого пользователя описание размером 4096 байт, которое теперь не читается. в замер входит запись 1000 заданий; очистка очереди выполняется вне таймера. это суммарные выделения за операцию, а не размер постоянно занятой памяти процесса.

сырые результаты: [метрики и синхронизация до](benchmarks/nodes-before.txt), [после](benchmarks/nodes-after.txt), [идентификаторы до](benchmarks/users-before.txt), [после](benchmarks/users-after.txt).

для повторения на текущем коде:

```sh
cd backend-go
GOMAXPROCS=1 go test ./internal/nodes -run '^$' -bench 'Benchmark(CloneMetrics|ReconcileUsers)$' -benchmem -count=5
GOMAXPROCS=1 go test ./internal/users -run '^$' -bench BenchmarkGenerateShortUUID -benchmem -count=3
```

для исходного замера те же файлы `metrics_test.go`, `reconcile_test.go` и `password_test.go` были перенесены в отдельную копию исходного кода. производственный код этой копии не менялся.

## запуск с 1 CPU и 2 ГБ RAM

готовый Docker-образ собран из репозитория, включая ресурсы редактора. контейнер работает от UID 10001, с файловой системой только для чтения, отдельным каталогом SQLite и лимитами `--cpus=1 --memory=2g --memory-swap=2g --pids-limit=128`. выход за лимит памяти не допускает использования swap.

данные созданы через API: 1000 активных пользователей с описаниями по 512 байт, один профиль, один внутренний сквад и один VLESS-хост. реальные узлы не подключались. история запросов подписок включена; отдельный HTTP-порт Prometheus выключен через `METRICS_ENABLED=false`.

локальный клиент на Python использовал восемь параллельных HTTP-соединений с повторным использованием соединений. каждый сценарий длился 20 секунд. проверялись HTTP 200, JSON в ответах API и наличие `vless://` после декодирования подписки.

| сценарий | запросов | запросов/с | p95 | ошибок | максимальный RSS во время сценария |
| --- | --- | --- | --- | --- | --- |
| смешанные чтения | 33 216 | 1660,5 | 15,684 мс | 0 | 44,7 МиБ |
| подписки | 31 981 | 1598,8 | 15,735 мс | 0 | 44,9 МиБ |

смешанный сценарий поровну обращался к `/api/system/health`, странице из 25 пользователей `/api/users`, одному пользователю `/api/users/{id}`, `/api/system/stats` и публичной подписке `/api/sub/{shortUuid}`. отдельный сценарий запрашивал ту же подписку с одним хостом.

максимум RSS за всё время жизни процесса, включая создание данных, составил 68,1 МиБ. контейнер не перезапускался и не завершался из-за нехватки памяти. каталог приложения занял около 66,4 МиБ, тестовая база с сопутствующими файлами около 5,6 МиБ. [сырые результаты HTTP-проверки](benchmarks/http.json).

дисковая квота в 30 ГБ не эмулировалась. проверка показывает запуск и работу этих сценариев в пределах 1 CPU и 2 ГБ RAM. она не определяет предел числа пользователей, нагрузку от реальных узлов, скорость сети VPS или рост истории за месяцы работы. нагрузка PostgreSQL проверялась функциональными тестами, без такого ограничения ресурсов.

## выполненные проверки

- `go test -race -count=1 ./...` на SQLite и PostgreSQL 18, `go vet ./...`, `gofmt -l .`, сборка `./cmd/server` с `CGO_ENABLED=0`.
- откат всей синхронизации при ошибке записи 550-го задания, обработка пропусков ID, отключённых пользователей и повтор неудачных заданий. проверена изоляция вложенных данных метрик.
- `bun run check`, `bun run typecheck`, 24 frontend-теста, производственная сборка, браузерные проверки в Chrome. браузерный набор также прошёл три последовательных прогона после исправления запуска.
- выгрузки команд и OpenAPI совпали с сохранённым контрактом `3.4.15`. на каждой базе проверено 88 ответов чтения и 182 ответа операций изменения, всего 540 ответов.
- проверка брендинга, синтаксиса установщика, его тестовых сценариев и схем заголовков Response Rules.
- сборка Docker-образа; отдача SPA и WASM из сжатого файла в готовом контейнере; открытие панели, регистрация администратора и создание демонстрационных пользователей через настоящий backend.
- главная и список пользователей просмотрены в браузере. на главной при ширине 390 пикселей ширина документа также составляет 390 пикселей. снимки в README сделаны при ширине 1440 пикселей.

после перевода ссылок и обновлений на `sorried/gowave-light` Docker-образ пересобран, а HTTP-проверка повторена с теми же лимитами. выполнено 34 463 смешанных запроса и 31 647 запросов подписки без ошибок. [повторный прогон](benchmarks/http-fork.json).
